# 成都气象环境AI招聘信息日报

每天自动搜索成都地区气象/环境/大模型/AI agent 领域招聘信息，按条件筛选后生成 HTML 报告并推送微信通知。

## 运行在 GitHub Actions 上，完全免费，电脑关机也能运行。

### 技术方案：Playwright 无头浏览器 + GLM-4-Flash 智能筛选 + 5轮搜索合并

---

## v8 更新内容

- **链接验证机制**：LLM筛选后，对每个链接发HTTP请求验证是否指向真实职位页面（检查HTTP状态码、重定向、页面内容关键词），验证失败的链接直接剔除
- **同企业多岗位独立卡片**：同一企业不同岗位各自独立展示为单独卡片，不再合并
- **爬虫链接选择器修复**：所有平台爬虫移除通用`a`标签回退，改用平台特定的职位链接选择器，避免抓到公司页/导航等错误链接
- **URL规范化**：新增`_normalize_url`处理协议相对URL（`//`开头），在数据入库、LLM匹配、卡片渲染4个环节统一规范化

## v7 更新内容

- **5轮搜索**：每日凌晨 2:00 / 3:00 / 4:00 / 5:00 / 6:00 五轮搜索，关键词分配到不同轮次
- **9:00 合并推送**：5轮搜索全部完成后，早上9:00合并去重、LLM筛选、生成HTML、推送微信（仅1次）
- **搜索范围扩大**：不限定国企央企，搜索所有类型企业。国企/央企/外资/合资不变，研究所增加学校（大学/学院归为研究所），其余统一归类为"其他"
- **其他类别薪资门槛**：其他类别月薪≥1.8万，现有类别薪资门槛不变（≥1.2万）
- **其他类别排最下方**：排列顺序为 国企→央企→外资→合资→研究所→待确认→其他
- **新增学校企业库**：成都信息工程大学、四川大学、电子科技大学、西南交通大学、成都理工大学、四川师范大学

## v6 更新内容

- **薪资正则过滤修复**：重构薪资解析器，正确处理混合单位（如"8千-1.2万"）、日薪/时薪等格式
- **HTML卡片式重设计**：紫色渐变头部、统计卡片、按公司类型分组展示、hover动画
- **排除博士学历**：要求博士/PhD的岗位排除
- **行业过滤库**：排除互联网金融/游戏/智能驾驶/证券期货/广告传媒/法律财务等行业
- **HR活跃过滤**：7天内不活跃的HR岗位过滤掉
- **卡片信息优化**：岗位职责+任职要求分行展示，不显示专业要求

## v5 更新内容

- **排除互联网大厂**：华为/阿里/腾讯/字节/百度/京东/美团/网易/小米/科大讯飞/商汤等全部排除
- **排除年龄限制**：要求35岁以下的岗位排除
- **排除党员要求**：仅限党员/须为党员/党员优先的岗位排除
- **双重过滤**：预过滤（关键词匹配）+ LLM筛选 + LLM后二次过滤

## 部署步骤（约 10 分钟）

### 第一步：创建 GitHub 仓库

1. 登录 GitHub
2. 点击右上角 **+** → **New repository**
3. 仓库名填 `chengdu-job-tracker`
4. 选择 **Public**（公开仓库免费额度无限）
5. 勾选 **Add a README file**
6. 点击 **Create repository**

### 第二步：上传项目文件

```
chengdu-job-tracker/
├── .github/workflows/daily-jobs.yml   ← GitHub Actions 工作流（5轮搜索+1轮推送）
├── main.py                             ← 主脚本（v7 5轮搜索 + 结构化筛选）
├── requirements.txt                    ← Python 依赖
├── .gitignore
└── reports/                            ← 报告输出目录（含 raw/ 子目录存中间结果）
```

### 第三步：配置 Secrets（密钥）

1. 进入仓库 **Settings** → **Secrets and variables** → **Actions**
2. 添加：

| Name | Value |
|------|-------|
| `ZHIPU_API_KEY` | 智谱 API Key |
| `SERVERCHAN_KEY` | Server酱 SendKey |

### 第四步：启用并测试

1. 进入 **Actions** 标签页
2. 点击 **成都招聘日报** → **Run workflow**（默认轮次6=完整流程）
3. 等待执行完成，检查 `reports/` 目录和微信通知

## 技术架构

```
GitHub Actions (5轮搜索 cron: 2:00-6:00 + 1轮推送 cron: 9:00)
    ↓
轮次1: 气象关键词      → 51job/猎聘/智联 → 1/5企业官网 → 保存JSON
轮次2: 环境关键词      → 51job/猎聘/智联 → 1/5企业官网 → 保存JSON
轮次3: AI/大模型关键词  → 51job/猎聘/智联 → 1/5企业官网 → 保存JSON
轮次4: 深度学习/ML关键词 → 51job/猎聘/智联 → 1/5企业官网 → 保存JSON
轮次5: 气候/算法关键词  → 全平台+成信大  → 1/5企业官网 → 保存JSON
    ↓
轮次6 (9:00): 合并5轮结果 → 去重 → GLM-4-Flash结构化筛选
    ↓
预过滤(大厂黑名单/年龄/党员/博士/行业/薪资) + LLM筛选(idx匹配真实链接) + LLM后二次过滤
    ↓
链接验证(HTTP请求检查每个URL: 状态码/重定向/页面内容关键词, 失败的剔除)
    ↓
按公司类型排序(国企→央企→外资→合资→研究所→待确认→其他) → 生成HTML报告
    ↓
Server酱 → 推送微信通知（仅1次）
    ↓
git commit + push → 报告存入仓库
```
